## 第二轮：配置模块与校验入口

将原 `core/src/config.rs`（1,775 行）拆为 `config/`，公开入口 96 行：
`defaults` 保存平台默认值与限制，`schema` 保存字段及 Serde 定义，`load` 处理分层，
`validate` 处理约束，`error` 保存错误类型，`example` 和 `example.toml` 保存示例模板。
现有公开声明与示例模板内容均核对保留，现有配置优先级和默认值不变。

新增共用的 `ConfigFile` provider，供 Server 与 Agent 使用，避免维护两套文件判断：

- 只读取精确路径，不向父目录搜索；支持普通文件及指向普通文件的符号链接。
- `optional` 仅在文件不存在时跳过，权限、路径错误如实报告。
- `required` 在文件缺失时也报错；Agent 显式传入的配置使用这一路径。
- 目录、设备等非普通文件在读取前拒绝，错误中保留配置路径。

原 Server 会把目录、无效路径当成“首次启动”；原 Agent 即使显式给了目录，
仍可能使用命令行必填项成功启动。新增测试先复现这些问题，再验证修复。
原有正常文件、缺省文件缺失、环境/CLI 优先级和示例配置等测试继续通过。

另外修复 `strixmaid agent --check-config`：过去全局参数被接受，但 Agent 分支
没有检查它，会进入数据库和采集启动流程。现在加载校验后立即退出，正常 Agent
运行仍走原有流程。新增真实可执行文件测试，带超时及子进程回收，检查两种模式
成功后均不创建数据目录、非法路径返回非零、Agent 不接受 Server 专属的 `--listen`。

配置相关 31 项 core 测试、9 项 Agent 测试、3 项 CLI 子进程测试通过。
最终全量验证：552 项单元/集成测试通过、2 项 ignored；另有 3 项 doctest 通过、
4 项 ignored。Clippy（workspace / all-targets，-D warnings）、严格 rustdoc、debug
和 release workspace 构建均通过。额外使用真实 release 二进制检查 Server 与 Agent：
有效配置成功退出、目录配置非零退出，均不创建数据目录。
