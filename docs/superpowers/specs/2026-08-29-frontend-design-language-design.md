# StrixMaid 前端设计语言

> 定稿日期：2026-08-29。本文是全站视觉与交互的唯一真相来源。
> 与 `design.md` §4、`roadmap/08-metrics-and-panel.md` §7 冲突之处，**以本文为准**，冲突项逐条记在 §13。
> 每一条数值都经过实算（对比度、色相夹角），不是估计。

---

## 1. 产品论点

**一个服务管住服务器的常见方面。** 不是「又一个监控面板」，而是一体化、轻量、跨平台的管理入口。

气质上的类比是 systemd —— **一体化、统一抽象、单一入口**。但那只是气质：
`systemd` / OpenRC / sysvinit / launchd / SCM 都是**服务的来源**，不是产品的抽象。

> **界面里禁止出现任何一个平台的方言。** 说「服务」不说 `unit`，说「系统日志」不说 `journal`。
> 平台名只能作为一个只读的「来源」标签出现，不能作主语，不能出现在按钮、标题、导航里。
> 错误提示中的命令由服务端按探测结果下发，前端不硬编码任何平台的命令。

界面是仪表的外壳，不是内容本身。外壳保持无彩、直角、发丝线；**所有的彩色都是被测量出来的东西**。

## 2. 色彩

### 2.1 三层预算

**一个像素只能属于一层。** 这是整套语言里最硬的规则。

| 层 | 内容 | 允许出现在 | 禁止出现在 |
|---|---|---|---|
| **中性层** | ground / surface / surface-2 / surface-3 / line / line-strong / sel / ink / ink-2 / ink-3 | 一切界面结构 | — |
| **身份层** | 发行版色（见 §2.2） | 顶栏的方形标记、登录页、节点列表 | 其它任何地方 |
| **数据层** | 五资源色 + 三状态色 | 图表、成员格、状态点、计数徽标 | 导航、边框、标题、普通按钮 |

**唯一的例外**（2026-08-29 定）：**破坏性操作的确认动作**可用 `--crit` 作实心底。
仅限「强制终止 / 屏蔽 / 关机 / 删除」这一类，且仅限确认框里的那一个按钮与触发它的那一个按钮。
别处一律禁止——这个口子不封死会漏成到处是红按钮。

推论：**普通按钮没有品牌色**。主按钮是 `--ink` 实心，次按钮是 1px 描边。

### 2.2 中性色由发行版主色派生

中性色不定死色相，而是**取该机器发行版主色的色相，抽掉绝大部分彩度**。
于是每台机器的灰都带着它自己的温度，但没有一处会被读成「有颜色」。

这不是装饰。多机运维最经典的事故是「我以为我在测试机上敲的」，**色温比任何文字提示都快**。

```
发行版主色 → 取 OKLCH 色相（彩度、明度丢弃）→ 按 §2.3 的明度阶铺开
```

| 发行版 | 主色 | 色相 H |
|---|---|---|
| Ubuntu | `#E95420` | 37.8 |
| RHEL | `#EE0000` | 29.2 |
| Debian | `#D70A53` | 11.5 |
| openSUSE | `#73BA25` | 132.6 |
| Alpine | `#0D597F` | 237.6 |
| Arch | `#1793D1` | 238.4 |
| Fedora | `#51A2DA` | 241.4 |
| **认不出** | — | **纯灰，C = 0** |

**彩度写死，不给用户调**：暗色 `C = 0.005`，亮色 `C = 0.004`（浅底对低彩度更敏感）。
`ink*` 三档取 `C × 0.55`（高彩度的文字会显脏），`sel` 取 `max(C, 0.010) × 1.7`。

可用区间只有三个千分点宽，实测：`C ≤ 0.008` 全部安全，`C = 0.012` 出现同侧，`C = 0.018` 出现撞色。
**暴露给用户等于让他把产品调坏。**

**认不出就不猜。** 自编译内核、容器里跑、小众发行版都会认不出，猜错色比不猜更糟。

**多节点**：界面色取**当前会话所认证的那个节点**的发行版色。这与认证模型天然一致——
`design.md` §5.1 已规定「登录会话天然是针对某个节点的」。

### 2.3 明度阶与实际色值

以 Ubuntu（H 37.8）为例。其它发行版只换 H，L 与 C 完全相同。

**暗色**（主）· C 0.005

| token | L | 色值 |
|---|---|---|
| `--ground` | 22.4% | `#1E1B1A` |
| `--surface` | 26.4% | `#272423` |
| `--surface-2` | 30.4% | `#312E2D` |
| `--surface-3` | 35.4% | `#3E3B3A` |
| `--line` | 37.4% | `#43403F` |
| `--line-strong` | 52.4% | `#6D6968` |
| `--sel` | 44.0% | `#5B4F4C` |
| `--ink-3` | 63.0% | `#8B8888` |
| `--ink-2` | 79.0% | `#BCBAB9` |
| `--ink` | 92.0% | `#E6E4E3` |

正文对面板 **12.16:1**，最弱一档字对面板 **4.38:1**。

**亮色** · C 0.004　（2026-08-29 修订，见下方「为什么改」）

| token | L | 色值 |
|---|---|---|
| `--ground` | 88.0% | `#DAD6D5` |
| `--surface` | 93.0% | `#EAE7E6` |
| `--surface-2` | 89.5% | `#DFDBDA` |
| `--surface-3` | 85.0% | `#D0CDCC` |
| `--line` | 82.0% | `#C6C3C2` |
| `--line-strong` | 64.0% | `#8E8B8A` |
| `--sel` | 78.0% | `#C2B4B0` |
| `--ink-3` | 48.0% | `#5F5D5D` |
| `--ink-2` | 34.0% | `#393737` |
| `--ink` | 24.0% | `#201F1E` |

正文对面板 **13.38:1**，次要 **9.61:1**，最弱一档字对面板 **5.32:1**。

**为什么改。** 原来的面板底是 `L99.5` ≈ 纯白 `#FFFDFB`，而面板是屏幕上面积最大的东西；
正文对它 **17.81:1** 也高出了长时间阅读的舒适区（约 10–14:1）。实测反馈是「刺眼」。

真正把中性色顶在那个亮度上的**不是中性色自己，是数据色**：面板底一旦低于 `L96.5`，
CPU 的青 `#0C97AB` 就先破 3.0 的门槛。所以这一轮**连亮色档的数据色一起压深**（见 §2.4）。

**`ink` 三档跟随全局明度调整，但钳在上限 L92**（暗）/ 下限 L20（亮）。
当前的明度调整量已固定，故实际取值即为 L92 / L20。
纯白正文在暗底上会产生光晕，**钳位是硬约束，不是默认值**。

### 2.4 数据色（不变）

沿用 `roadmap/08` §7.2 的五资源色与三状态色。**那套色的相邻序是穷举验证过 protan / deutan / tritan 的，
不因为换视觉方向而重来。**

| | CPU | GPU | 内存 | 磁盘 | 网络 | 正常 | 警告 | 严重 |
|---|---|---|---|---|---|---|---|---|
| 暗 | `#12A6BA` | `#4E9A3D` | `#8A6FE0` | `#C0762A` | `#C25086` | `#4BB07A` | `#D9A227` | `#E86B60` |
| 亮 | `#00798C` | `#1F680F` | `#5F3DB2` | `#904D00` | `#92255C` | `#005E25` | `#6C4500` | `#A10000` |

**亮色档在 2026-08-29 整体压深了 OKLCH 明度 10**（原值见 git 历史）。
色相与彩度**一个都没动**，所以「相邻序」那套结论继续成立。压深的收益是双向的：

| | 压深前 | 压深后 |
|---|---|---|
| 面板底 | `L99.5` `#FFFDFB` | `L93.0` `#EAE7E6` |
| 正文对面板 | 17.81:1 | 13.38:1 |
| 最弱数据色（CPU）对面板 | 3.43 | **4.15** |
| 相邻序最差 ΔE00（protan/deutan/tritan 取最差） | 5.8 | **5.6** |

即：眩光降下来的同时，数据色对面板的对比度**不降反升**，色盲分离度只掉 0.2。

亮色档压深后各数据色对面板 / 对页底：CPU 4.15/3.54、GPU 5.61/4.78、内存 6.10/5.21、
磁盘 5.26/4.48、网络 6.46/5.51、正常 6.50/5.54、警告 6.86/5.85、严重 6.79/5.79，全部 ≥ 3.0。

> 本轮的 CVD 分离度用 **Viénot–Brettel–Mollon 1999 模拟 + ΔE00** 计算。
> 这与 `roadmap/08` §7.2 当初那次穷举所用的度量**不是同一个**，绝对值不可跨文档比较；
> 这里只用它做**改动前后的相对比较**，结论是「几乎没变」。

在 §2.3 的新底上实测（暗色 · 对 ground / 对 surface）：

| CPU | GPU | 内存 | 磁盘 | 网络 | 正常 | 警告 | 严重 |
|---|---|---|---|---|---|---|---|
| 5.86 / 5.28 | 4.90 / 4.41 | 4.43 / 3.98 | 4.78 / 4.30 | **3.90 / 3.51** | 6.35 / 5.72 | 7.46 / 6.71 | 5.46 / 4.92 |

全部高于图形元素 3.0 的下限。**余量最小的是网络的品红（3.51）**——记为已知项，不调整。

### 2.5 撞色约束

界面底带色相后，与它色相接近的数据色会「黏」在背景上。实测各发行版的最近邻：

| 发行版 | 最近的数据色 | 夹角 | 彩度差 |
|---|---|---|---|
| Ubuntu | **严重（红）** | 11° | 26× |
| Debian | 严重（红） | 16° | 26× |
| openSUSE | **GPU（绿）** | 7° | 25× |
| Arch | CPU（青） | 28° | 19× |
| Fedora | CPU（青） | 31° | 19× |

夹角虽小，但界面彩度只有数据色的 1/25，眼睛分得开。**这个结论只在 `C ≤ 0.008` 时成立**，
这就是彩度必须写死的原因。

> 注意 Ubuntu 上最近的是**「严重」红**而不是磁盘琥珀——红是最需要跳出来的色。
> 任何调整彩度的提议都必须重跑这张表。

### 2.6 图表底板改为中性

`roadmap/08` §7.2 原规则是图表底板 `color-mix(资源色 7%, surface)`。**废止。**
`surface` 现在自带发行版色相，两个色相叠加会发脏。资源身份由曲线本身、标题与四角标注承担。

## 3. 排版

### 3.1 字体

| 角色 | 字体 | 体积 |
|---|---|---|
| 界面（正文、标签、按钮、中文） | 系统栈 | 0 |
| 数据（数字、主机名、设备名、路径、命令、指标 id） | **IBM Plex Mono**（内嵌，latin 子集） | 10.0 KB |

```css
--ui  : system-ui, -apple-system, "Segoe UI",
        "PingFang SC","Microsoft YaHei UI","Microsoft YaHei",
        "Hiragino Sans GB","Noto Sans CJK SC", sans-serif;
--mono: "IBM Plex Mono", var(--cjk), ui-monospace, Menlo, monospace;
```

**界面字不内嵌**：界面文字九成是中文，中文只能走系统字，为那一成拉丁内嵌 35 KB 不划算。

**等宽字必须内嵌**：表格数字对齐是刚需，系统等宽跨平台差异极大（SF Mono / Consolas / 可能没有），
列宽会在不同机器上跳。IBM Plex Mono 零带斜杠（`0` 与 `O` 一眼分开，设备名里两者都出现），
比 JetBrains Mono 窄且子集只有其 1/3。

**不使用衬线 / 宋体。** 风格过重，且横画在 12px 下会糊，而本界面九成的字在 11–13px。

### 3.2 字号阶梯

只有这七级，不许插值：

```
10  mono  大写 letter-spacing .16em   分区标签、单位、表头
11  mono                              数据小字、路径、设备名
12  sans / mono                       表格正文
13  sans                              界面正文、按钮
15  sans                              段落说明
19  sans  600                         页面标题
28+ mono                              大读数
```

数字全局 `font-variant-numeric: tabular-nums`。

## 4. 空间与形

- 间距只用 **4 的倍数**：`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24`。
- 行高三档：**导航行 30px、表格行 30px、工具条 40px**。**不提供密度开关**——
  两档密度意味着每个组件两套间距、两倍验证，最后两档都是二流。
- `border-radius: 0` **全局无例外**，包括图表末点（6px 方块）、状态点（8px 方块）、头像、进度槽。
- 线宽三档，各有固定含义：

| 线宽 | 含义 |
|---|---|
| 1px `--line` | 普通分隔 |
| 1px `--line-strong` | 控件边框、表头下沿 |
| 2px `--ink` | 「这是主的 / 当前的」 |

**边条（3px 实色左条）从设计语言中删除。** 选中一律用「提亮底 + 字重加粗」，见 §5.3。

## 5. 组件

### 5.1 按钮

| 类型 | 样式 |
|---|---|
| 主 | `--ink` 实心，`--ground` 文字 |
| 次 | 透明底，1px `--line-strong` 边 |
| 禁用 | `--ink-3` 文字，`--line` 边，透明底，`cursor: default` |
| **破坏性** | `--crit` 实心（暗色配 `#1A0E0C` 文字 6.03:1；亮色配白字 **8.35:1**） |

破坏性操作**必须**弹二次确认框，框里说清后果（哪个信号、会丢什么），不只是「确定吗」。

### 5.2 表格

**斑马纹，不画行线。**

```
奇数行 --surface (L26.4)  →  偶数行 --surface-2 (L30.4)
划过   --surface-3 (L35.4)  →  选中 --sel (L44)
```

四级阶梯都能分开，但**奇偶行只差 4%，这是全套语言里最紧的一处**，实现时必须逐像素核对。
表头下沿 1px `--line-strong`，表体内不画横线。

长文本（cmdline / 路径）**中间截断**，不用尾部截断——尾部截断会切掉最有信息量的文件名。

### 5.3 选中与划过

两个状态**都用底色**，靠明度阶梯区分（见 §5.2）。选中行额外**加粗主字段**。
不使用边条、不使用反色。导航、表格、成员格全部统一到这一种手段。

### 5.4 焦点

**2px `--ink` 实线 outline，`outline-offset: 2px`。全站唯一样式，无例外。**

留 2px 空是必需的：贴边会和控件自己的 1px 边框糊成「边框变粗了」。
这是全站唯一一处「必须显眼到有点粗暴」的视觉。

### 5.5 浮层

**双层阴影**，两个主题都用：

```css
/* 暗 */ 0 1px 1px rgba(0,0,0,.5),  0 9px 26px rgba(0,0,0,.62)
/* 亮 */ 0 1px 1px rgba(0,0,0,.10), 0 9px 26px rgba(0,0,0,.16)
```

配 1px `--line-strong` 边框。对话框加 `rgba(0,0,0,.45)` 全屏遮罩，下拉与菜单不加。

> 暗色下投影本来会看不见，是 `--ground` 提到 L22.4 之后才有了落脚点。
> **任何调暗 `--ground` 的提议都会同时废掉阴影**，两者绑定。

### 5.6 图标

**Lucide**，按需内联，统一改为 `stroke-width: 1.3`、`stroke-linecap: butt`、`stroke-linejoin: miter`。
Lucide 默认圆头端点，**必须改**，圆头与本语言冲突。

图标只出现在导航与少数高频操作上。状态一律用几何标记（实心方块=运行、描边方块=停止、实心方块+严重色=失败），不用图标。

**不使用任何发行版的商标图形。** 发行版身份 = 色 + 首字母方块（16px，色盲下也能认）。
若将来要用真 Logo，须逐个确认商标许可，单独立项。

## 6. 状态语言

`design.md` §6 的区分必须贯彻到底，两者体验完全不同：

| 情形 | 表现 |
|---|---|
| **能力不存在**（探测不到服务管理器 / 无 GPU） | **整块不出现**。不是灰掉，是不存在 |
| **有能力但无权** | **显示但禁用** + 说清缺什么组 + 给提权入口 |
| **首次加载** | 骨架屏 |
| **刷新（已有数据）** | **保留数据不换骨架**，否则每次轮询整表闪一下 |
| **空** | 说清为什么空 + 一个可做的动作 |
| **出错** | 说清发生了什么 + 一条可执行建议 |

措辞规范：

- 空态**不写「暂无数据」**——那是系统在描述自己。
  写：`没有匹配「nginx-proxy」的服务。这台机器上共有 312 个服务。` + 「清除搜索」。
- 错误**不道歉、不含糊**。
  写：`读取服务列表失败。与服务管理器的连接被拒绝，可能是它尚未启动。` + 一条命令 + 「重试」。
- **命令由服务端按探测到的平台下发**，前端不硬编码。

## 7. 动效

只有三处，其余一律没有：

| 处 | 时长 |
|---|---|
| 状态色变化 | 120ms |
| 浮层出现 | 90ms |
| 加载进度线 | 循环 |

图表数据更新**不做动画**，直接重绘（2s 一帧本来就够慢）。
`prefers-reduced-motion` 下全部关闭。**不引入动画库**——三处过渡用 CSS 即可，
为它引入 40–50 KB 的运行时与「轻量」这个产品论点直接矛盾。

## 8. 响应式

| 宽度 | 布局 |
|---|---|
| ≥ 900px | 左栏 184px + 内容区；内容区自带二级导航 |
| < 900px | **左栏折叠成 44px 图标条**，导航始终可见，一次点击可达 |

图标条是图标质量唯一真正影响可用性的地方，每个图标必须带 `title`。

窗体**自适应视口**（`100dvh`），内容区 `.d-body` 独立滚动并设 `scrollbar-gutter: stable`
——否则内容一超高滚动条弹出、容器宽度骤变，所有 uPlot 图会跟着跳一下宽度。

---

## 9. 数据呈现

- **字节一律 1024 进制，明确标 `GiB` / `TiB`。** 宁可用户多认一个字母，
  也不要同一块盘在两个页面显示成 1.82 TB 和 2.00 TB。
- **唯一例外**：网络速率按惯例用 1000 进制的 `Gb/s`。
- 数值与单位之间一个窄空格，单位小一号、灰一档。
- 时间默认相对（「3 分钟前」），悬停出绝对时间（ISO 8601 带时区）。

---

## 10. 无障碍

- 焦点样式见 §5.4，`:focus-visible`，不得用 `outline: none` 而不给替代。
- 可点击的表格行 / 成员格：`role="button"` + `tabIndex=0` + Enter / 空格。
- ≥2 条 series 的图表必有图例；单条不需要（标题已命名它）。
- 每张图下提供 `<details>` 表格视图。
- **颜色从来不是唯一的身份编码**：每个状态点旁必有文字，每个资源色旁必有名称。

## 12. 实施顺序

`v1 纵向切透`：**登录页 + 性能面板**先做到成品级。

理由：这一条链一次性逼出全部地基——token 与两套主题、发行版派生、WS 订阅与重连、
uPlot band、能力探测退化、虚拟滚动。地基铺好后，其余八个页面都变成套模板。

登录页采用**双栏**（左暗右亮）：左栏放主机身份与**能力探测结果**，右栏放表单。
`GET /api/v1/capabilities` 未认证时本来就返回 `system` 层，**登录页是它唯一的展示位**；
helper 不可用时清单里那一行变红、右栏不渲染输入框——不给一个按下去必失败的框。
