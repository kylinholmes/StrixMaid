# 11 多主机：管道、远程推装、B 侧会话

> 前置：`10-node-layer.md`。本方案假定 `strixmaid-node` 已经存在，且 agent 与 server 提供同一个 `Router`。

## 1. 目标

在 Server（主机 A）的面板里添加一台空白主机 B，输入 B 上的账户口令，自动装好 agent；此后 B 在面板里与 A **完全等价**——指标、进程、服务、日志、终端、服务启停全都可用，只是数据从 B 那边来。

这推翻了 `design.md` §11 末尾的两条 MVP 限制（「HTTP 路径不带节点标识」「Agent 仅只读采集，不接受远程管理操作——有真实场景再设计」）。真实场景就是本方案；§11 已按本方案改写。

原 `05-agent.md` 描述的「Agent 只读」形态被本方案取代，该文件已删除（内容已落进代码，考据走 git 历史）。

## 2. 四条已定的约束

实施前拍板的四件事，后面所有设计都从它们推出来，不要重新讨论：

| # | 决定 | 推论 |
|---|---|---|
| 1 | B 上要有**完整**能力，观测与管理都要 | B 上必须有 helper、认证链、worker 派生。agent 从「采集器」长成「无 UI 的 server」 |
| 2 | 操作者用 **B 的本地账户**，凭据**不落 A** | 认证对话经 A 透传，`LogonUserW` / PAM 在 B 上发生。A 看到的是不透明字节 |
| 3 | 推装走 **SSH**，一统三平台 | Windows 侧要求 B 开了 OpenSSH Server（Win10 1809+ 自带，默认不启用） |
| 4 | A 是**管道**不是翻译器 | A 不为任何端点写转发代码。B 上跑的是完整 `Router`，A 只搬字节 |

约束 4 是本方案的支点：它把「B 上的 API」与「字节怎么到 B」彻底解耦。若将来 B 入站可达，同一个 `Router` 绑到 TCP 上即可，本方案的任何决定都不必回退。

## 3. 设计

### 3.1 管道

B 拨号到 A（沿用今天的方向，NAT 后的 B 因此可用）。那条 WS 现在要同时承载三类流量：指标推送、API 请求、WS 流（终端与 live 频道）。一条连接上跑多路，需要**带流控的多路复用**——没有流控的话，一个刷屏的终端会把指标推送饿死。

不自己写。用 `yamux` 跑在 WS 之上：

```
浏览器 ──HTTPS──▶ A: /nodes/B/api/v1/services
                     │
                     ├─ A 开一条 yamux 逻辑流
                     ├─ 把 HTTP 请求原样写进去
                     ▼
                  ┌──────────────── WS（B 拨过来的）────────────────┐
                  │  yamux: 流 1 指标推送 · 流 2 本次请求 · 流 N …   │
                  └───────────────────────────────────────────────┘
                     ▼
                  B: 把这条流当作一个连接交给
                     hyper::server::conn::http1::serve_connection(stream, router)
```

B 侧**没有任何转发逻辑**——它收到的就是一个 `AsyncRead + AsyncWrite`，上面跑着真正的 HTTP，交给 `Router` 处理。这也是为什么 10 号方案要把 API 的单位定成 `Router`。

WS 升级（终端、live 频道）同样成立：流里跑的是真 HTTP，`Upgrade: websocket` 端到端有效。A 接下浏览器的升级后，在对应的 yamux 流上把升级请求转出去，此后两侧对泵帧。**一份对泵代码管所有流式端点**，不是每个功能一份。

### 3.2 节点路由

| 路径 | 去向 |
|---|---|
| `/nodes/local/api/v1/**` | 进程内直调 A 自己的 `Router`，不绕 TCP |
| `/nodes/<id>/api/v1/**` | 经管道到该节点 |
| `/api/v1/**` | 等价于 `/nodes/local/api/v1/**`，保留兼容 |

前端眼里 A 与 B 完全一样，UI 不分两套。

### 3.3 认证与会话

约束 2 的直接后果：**每个节点一套会话**。

`POST /nodes/B/api/v1/auth/login` 原样送到 B 的登录端点，B 的 helper 验证、B 签发会话 token、B 派生 worker。A 转发密文字节，不解析、不留存——「凭据不落 A」不需要额外机制，是这个结构的自然结果。

前端因此要持有 N 个会话 token（每节点一个），这是本方案对前端唯一的结构性要求。切到一个未登录的节点时弹该节点的登录框。

**提权**同理：`elevation_required` 由 B 返回，提权对话框里的口令送到 B。

### 3.4 审计落在 B

在 B 上发生的操作，审计记录写进 B 的库，由 B 的 `auth::exec` 写（10 号方案已把它搬进 node，行为不变）。A 的审计页面查 B 的审计，就是一次经管道的普通 API 调用。

这条是刻意的：审计必须与被审计的动作在同一台机器上落地，否则 A 与 B 之间断连的那段时间会成为审计空洞。

### 3.5 推装

面板上填 B 的地址与一次性凭据，A 经 SSH 完成：

1. **探测**：`uname -sm` / PowerShell 取 OS 与架构，决定要送哪个产物。
2. **传输**：把 agent 产物送上去（产物从哪来见 §5 未决 1）。
3. **安装**：按平台落文件、装服务（systemd unit / launchd plist / `sc create`）。复用 `packaging/` 下三套现成的安装脚本，不新写一套。
4. **配置**：A 生成节点 token，写 B 的 agent 配置，指向 A。
5. **启动**：拉起服务，等 B 拨号回来。面板上看到该节点上线即成功。

两条硬要求：

- **幂等**：同一台机器重复推装不出错，等价于升级。
- **可回滚**：任一步失败，把已做的步骤按逆序撤掉，不留半装状态。B 上装了一半的服务比没装更难处理。

一次性凭据**不入库、不进日志**，用完即焚（`design.md` §5.3 对明文口令的约束同样适用：只以 `Zeroizing<String>` 存在）。

### 3.6 断连

| 情形 | 处理 |
|---|---|
| B 短暂掉线 | B 上的会话与 worker **保留**。终端重连后回看缓冲续上（`03-terminal.md` 的会话保持机制在 B 本机照常工作） |
| B 长时间掉线 | 超过会话超时后由 B 自己清理，与本机会话同一套逻辑 |
| A 重启 | B 重新拨号；凭时间戳游标补发断连期间的指标（今天已有） |
| 前端正在看 B 却掉线 | 该节点的请求返回 `503 node_offline`，UI 显示离线而不是转圈 |

### 3.7 不做

- 不做「浏览器直连 B」。结构上留好了（同一个 `Router`），但本方案不实现第二条路径——两条路径都要测、认证与会话行为还要保持一致，收益不抵成本。
- 不做跨节点的身份映射（A 的用户自动映射到 B 的用户）。约束 2 已经排除。
- 不做 mTLS（原 `05-agent.md` 列为 P1，仍然 P1）。
- 不做节点分组、批量操作、跨节点聚合视图。

## 4. 测试

1. **等价性**：对 `local` 与对一个远程节点跑同一份 `scripts/api-smoke.sh`，输出除节点标识外一致。这是本方案的核心断言。
2. **管道流控**：终端持续刷屏时，指标推送的帧间隔不退化（无饥饿）。
3. **凭据不落 A**：登录一次远程节点后，抓 A 的全部日志与数据库，grep 不到口令。
4. **推装幂等**：同一台 B 连续推装两次，第二次成功且服务仍然正常。
5. **推装回滚**：在第 3、4、5 步各注入一次失败，B 上不留残留。
6. **断连**：拔网 30 秒再接上，终端会话续上且无字节丢失。

## 5. 未决问题

1. **agent 产物从哪来。** A 要把 B 平台的 agent 送上去，但 A 自己只带着自己平台的二进制。三个平台全打进 A 会让 A 涨约 20 MB。候选：从 release URL 拉（要求 A 能出网）、由操作者上传、或只支持同平台推装。**这一条必须在动工前定。**
2. **agent 的体积上限。** 装载完整 node 之后必然突破原 `05-agent.md` 的 8 MiB。新上限待定，建议按「不超过 `strixmaid` 的 90%」写，因为 agent 只比 server 少前端与节点目录。
3. **B 验证 A 的身份。** 今天 B 只校验 A 给的 token。A 若被冒充，B 会把管理请求当真。需要 B 侧固定 A 的证书（pinning）还是别的办法，未定。
4. **一个 B 连多个 A。** 结构上不禁止，但会话、审计、推装的语义都要重想。默认不支持，明确拒绝还是放任未定。
