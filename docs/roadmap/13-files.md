## 3. 字节通道（已批准）

主进程负责 HTTP 与流转发，所有文件 open/stat/seek/read/write 仍由会话 worker
以所选身份执行。主进程不得拿 root 身份按用户提供的路径直接打开文件。

```text
浏览器 ← HTTP body + Range → node ← 专用字节通道 → user worker ← 文件
                                  控制 RPC 只传元数据/请求/附件
```

读通道的控制请求包含 path、allowed_roots 和 preview 用途。
worker 打开普通文件，返回已打开句柄的元数据和一个通道附件；node 根据长度解析
Range，再经附件发送两个大端 u64（offset、length），worker 据此定位并开始搬运。
单次响应只读同一个已打开文件，不能逐块重新打开路径，否则移动/替换文件可能拼接
两个版本。FIFO、设备、目录、socket 不进入读流，避免打开特殊文件挂住任务。

主进程按固定大小缓冲转发；worker 泵受通道背压约束，不读完整文件到内存。
每会话并发读流初值 4、全 node 32；名额在启动任务之前取得，取消后释放。
断开 HTTP、注销、会话过期、worker 退出都关闭关联流。每条流有无进展超时，
不使用“下载总时长必须小于几十秒”这种会中断合法大文件传输的限制。

读写通过明确的操作类型区分，D 再实现写入：用户 worker 内创建目标目录的临时
文件，写完并确认长度后提交；取消/失败删临时文件。A 不为未来写入注册空壳接口。

## 4. 浏览器凭证：已批准方案

09-21 的“**一次性 URL 票据同时支持 Range**”不能直接照写：一次预览可能有
多个 GET/HEAD/Range 请求，第一次请求不能消耗掉后续读取资格。
Range/206/416 的协议依据为 [RFC 9110 §14](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)。

采用将 URL 与秘密分开的方案：**Bearer 创建文件访问记录 + 文件专用 HttpOnly Cookie**。

| 操作 | 凭证与作用 |
|---|---|
| `POST /api/v1/file-access` | Bearer；绑定当前会话、路径和 preview/download 用途，返回非秘密 id 与 URL，设置文件 Cookie |
| `GET/HEAD /api/v1/file-access/{id}/content` | 文件 Cookie + id；只可读取已绑定的那个文件，支持多个 Range 请求 |
| `POST /api/v1/file-access/{id}/renew` | Bearer；只允许所属会话续期，预览仍打开时由前端调用 |
| `DELETE /api/v1/file-access/{id}` | Bearer；关闭预览后释放该记录，不取消用户已明确开始的另一条下载 |

以上契约已同步 DTO、OpenAPI 和前端生成类型。

文件 Cookie 只用于这些读端点，不成为普通管理 API 的 Cookie 登录入口。
不写入长会话 Bearer：用进程内随机密钥与会话 hash 经 HMAC-SHA256 派生秘密，
并发初始化得到同一 Cookie；注册表仅保存摘要及所属会话 hash，密钥不持久化。
Cookie 设置 HttpOnly、SameSite=Strict、限定 Path、不设置 Domain；HTTPS 设置 Secure。
本地 HTTP 开发必须明确处理 Secure 属性，不能盲目信任任意 X-Forwarded-Proto。
Cookie 的发送范围和 HttpOnly 语义参见
[RFC 6265 §4.1.2](https://www.rfc-editor.org/rfc/rfc6265.html#section-4.1.2)。

每次读请求同时验证：Cookie 摘要有效、访问记录属于同一会话、会话仍有效、
记录未过期、用途匹配。Cookie Path 只约束浏览器发送范围，不能代替这些服务端检查。
记录和文件 Cookie 采用 10 分钟滑动有效期，访问记录仅由 Bearer 操作续期，
每会话最多 32 条，过期和注销时删除。新请求验证期限；已获准流继续受会话撤销、
无进展超时和并发上限约束。不能让注册表中的失效条目一直占名额。

同一会话的多次创建复用文件 Cookie；切换用户后 Cookie 可以被覆盖，但旧用户的
记录必须因为会话不匹配而失败，不能借新 Cookie 读到旧文件。
长会话 token、Cookie 值都不进 URL、日志或存储；访问 id 本身不授予读权限。

备选仍是“短期可多次使用的文件票据 URL”：实现较少，但 URL 本身持有读权限，
必须额外处理日志、复制链接和引用来源泄漏。它不是严格的一次性票据。
Cookie 方案是对原提案的细化，负责人已于 2026-09-29 明确批准，实施以本方案为准。

## 5. HTTP 与文件版本

首阶段支持单段 bytes Range（起止、开放结尾、suffix）、HEAD、200/206/416。
多段 Range 可按 RFC 9110 忽略并返回完整 200，不伪造单段 206。
HEAD 不启动数据泵。长度以 worker 打开后的元数据为准；短读必须报中断，不能
宣告成功；整数运算覆盖 4 GiB 以上偏移与空文件。

默认只发可证明的修改时间/弱版本标识，不把 size+mtime 冒充强 ETag。
不匹配或不能可靠验证的 If-Range 返回完整响应，不能拼接两个版本。
A 验收覆盖同一未改动文件的续传；不承诺对并发改写的文件做快照。

下载响应使用 attachment 和正确编码的文件名；预览仅对允许的 MIME inline。
HTML、SVG、未知类型不得作为同源可执行文档打开；文本内容用 React 文本节点，
不解释 HTML。PDF 使用受限嵌入，不能给任意文件“脚本 + 同源”权限。
统一 private/no-store、nosniff 和 no-referrer，禁用文件响应的自动压缩，避免 Range
偏移与 Content-Length 被压缩中间层改变。

## 6. A 阶段界面

普通文件双击/回车打开预览，单击仍选中；列表和平铺共用动作判定。
目录导航和已有符号链接“定位目标”的行为保留。设备、FIFO 等显示不可预览原因。
预览是工作区内的独立面板/对话框，显示名称、大小、关闭和下载按钮；关闭恢复焦点。
切换文件取消旧请求，退出登录/换账号关闭预览并释放 URL 与文件访问记录。

| 类型 | 显示方式 |
|---|---|
| 文本/代码 | 复用 content API，显示编码替换/超限原因；高亮器与语言包按需加载，失败回退纯文本 |
| 图片 | worker 生成约 1600px 预览档，沿用像素/解码内存/并发限制；原图下载走原始流 |
| HEIC | macOS 使用已有系统解码；Linux/Windows 无解码能力时显示下载入口，不伪称已支持 |
| PDF | 浏览器原生预览，验证 Range 和受限嵌入兼容性；失败有下载入口 |
| 音视频 | 原生 controls，使用读取 URL，验证 seek 后 Range；格式不支持给下载入口 |
| 其他/超大文本 | 文件信息与下载，不整文件构造 Blob |

先检查高亮器按语言加载后的实测产物，再确定依赖；不预先增加全部语法包。
保持发布物 18 MiB 门槛，不以 macOS 产物体积代替 musl 结果。
